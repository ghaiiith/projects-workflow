# منظومة إدارة المشاريع الحكومية | Projects Workflow

> **صندوق إعمار المحافظات الأكثر فقراً – مديرية الشؤون الهندسية والفنية**
>
> Arabic-first, RTL government project lifecycle platform using **IBM Plex Sans Arabic**, React, Node.js, Express and SQLite.

## نطاق النسخة الحالية (v0.1)

يحتوي هذا المستودع على **تطبيق أولي قابل للتشغيل والتجربة محلياً**، وليس نظاماً حكومياً معتمداً أو جاهزاً للإنتاج أو منصة مناقصات رسمية. يشمل:

- إنشاء مشاريع برقم فريد وبيانات الجهة المستفيدة والمنفذة والقطاع والمحافظة والقضاء والكلفتين التخمينية والكلية.
- مراحل: مسودة الإدراج ← التدقيق الهندسي ← لجنة الإدراج ← مصادقة الإدراج ← الإعلان ← استلام العطاءات ← فتح العطاءات ← التحليل ← المصادقة على الإحالة ← التبليغ والاعتراضات ← العقد ← المباشرة والتنفيذ ← الإنجاز.
- صلاحيات منفصلة لأدوار الأقسام واللجان، مع **منع الجمع عملياً بين الأدوار المختصة بفتح العطاءات وتحليلها والمصادقة على الإحالة عبر حساب واحد** في هذه النسخة.
- لجان إدراج لها أعضاء ونصاب محدد، تصويت منفرد وملاحظات ورقم دورة مراجعة؛ لا يتم الاعتماد قبل تحقق النصاب.
- رفع PDF وصور وWord وExcel، وأرشفة نسخ متعددة، وعرض اكتمال قائمة مستندات مستوحاة من الورقة المرفقة (16 بنداً في أصل القائمة) مع مستندات لاحقة للتعاقد.
- تسجيل الإعلان، قيد العطاءات، توصية التحليل، معلومات العقد، طلبات السلف، التدقيق الفني والمالي والتخويل وتسجيل الصرف.
- إعادة الملف خطوة أو رفضه بسبب معلل، سجل تدقيق، لوحة مؤشرات، ملفات ومرجعيات تشريعية.
- واجهة عربية RTL تستجيب للجوال والخط IBM Plex Sans Arabic محمّل من Google Fonts.

## التشغيل المحلي

المتطلبات: Node.js **22+** وأداة npm.

```bash
git clone https://github.com/ghaiiith/projects-workflow.git
cd projects-workflow
cp .env.example .env
# افتح .env وأدخل JWT_SECRET عشوائياً (32 رمزاً على الأقل)
# وأدخل BOOTSTRAP_ADMIN_PASSWORD قوية (12 رمزاً على الأقل)
npm install
npm run dev
```

- الواجهة: `http://localhost:5173`
- API: `http://localhost:4000/api`
- أول دخول باسم المستخدم `admin` ما لم تغيّره في البيئة، وبكلمة السر التي حددتها **أنت** في `.env`.
- للتشغيل بعد البناء: `npm run build && npm start`.
- الاختبارات: `npm test`.

> ملفات البيئة لا تُنشر في المستودع. لا توجد كلمات مرور افتراضية ولا بيانات حكومية فعلية.

### Docker

```bash
cp .env.example .env
# عدل القيم السرية
docker compose up --build -d
```

الواجهة وAPI على `http://localhost:4000`. قاعدة البيانات والمرفقات في volume محلي خاص. اضبط HTTPS وReverse Proxy وآليات نسخ احتياطي منتظمة قبل أي تعريض للشبكة.

## قائمة الوثائق الأساسية

استمارة المشروع، الكلفة التخمينية، الكلفة الكلية (حقول منظمة)، استمارة المشاريع الصغيرة أو دراسة الجدوى، الاستملاك، جداول الكميات المختومة والموقعة، أوامر اللجان، التعارضات، الحصة المائية، خلو الأرض من الشواغر، المخططات الفنية، الصور الجوية/مسارات الطرق، التقرير البيئي، الموافقة البيئية، فحوصات التربة/تقرير الهدم، أولويات الإدراج بكتاب من المحافظة.

نموذج البيانات يخزن القيم المالية بدينار عراقي، ويخزن الوثائق كملفات مرفقة منفصلة. توجد أيضاً قائمة للوثائق التعاقدية مثل محاضر الفتح والتحليل وقرار الإحالة وتبليغاتها وحسم الاعتراضات والعقد ومحضر المباشرة.

## نقاط تنظيمية مهمة يجب اعتمادها قبل التشغيل

1. **تعليمات تنفيذ العقود العامة رقم (1) لسنة 2025** نافذة منذ 15/02/2026 مع ضوابطها الملحقة؛ التعليمات رقم (2) لسنة 2014 ملغاة. لا تستخدم نماذج 2014 كأساس حصري للقرارات الجديدة.
2. نظام صندوق الإعمار رقم (5) لسنة 2023 وتعديله رقم (5) لسنة 2024 يحددان اختصاصات الصندوق والهيكل. النص المعدل يحيل إلى استثناء من مادة في تعليمات 2014 التي ألغيت لاحقاً؛ **تفسير أثر هذا الاستثناء يتطلب رأياً قانونياً مكتوباً**.
3. المرحلة التي تسمى «لجنة الإدراج» في التطبيق هي **لجنة داخلية افتراضية قابلة للضبط** وليست افتراضاً أن تشكيلها أو نصابها محدد بهذا الشكل في القانون؛ يجب إصدار أوامر التشكيل الواقعية.
4. تعليمات 2025 تفرق صراحةً بين لجان فتح العطاءات وتحليلها والمصادقة على الإحالة ولجنة الاعتراضات؛ يلزم إصدار أوامر تشكيل، تسجيل بدلاء، مراقبة انتهاء العضوية وتعارض المصالح.
5. التسجيل في شاشة «الإعلان» **ليس نشراً رسمياً**، والتسجيل في شاشة «الصرف» **ليس أمراً مصرفياً**. الربط مع المنصة الإلكترونية الموحدة، المحاسبة الحكومية، IDMS، الوثائق الرسمية ونظام التوقيع الإلكتروني ليس منفذاً بعد.
6. السلف المرحلية تتطلب في المادة (31) طلب مقاول إلى المهندس المقيم وتدقيقه وتأييد الإنجاز قبل الصرف، مع الاستقطاعات والضمانات حسب نوع العقد. النسخة الحالية تعرض سيراً عاماً لطلب السلفة ولم تنفذ **احتساب 10% أمانات حتى بلوغ 5% من قيمة المقاولة، أو الضرائب والضمانات أو السلفة المقدمة**. لا تستخدم قيمة «مصروف» كمعلومة مالية معتمدة.
7. مدة الاعتراضات على الإحالة في المادة (19) وإجراءات حسمها لا تُحسب في النسخة الحالية تلقائياً؛ يجب إدخال إثبات حسمها قبل استكمال العقد.
8. مسارات أساليب التعاقد البديلة (محدودة، دعوة مباشرة، عطاء وحيد، اتفاق إطاري وغيرها) تحتاج مخططات فرعية قانونية خاصة بها، وهي **ليست** مؤتمتة في النسخة الأولية.
9. لا توجد تكاملات بنكية أو تسويات، توقيع رقمي حكومي، قفل ملفات غير قابل للتغيير، نسخ احتياطي مجدول، MFA، SSO أو فحص مضاد للفيروسات. يلزم قبل الإنتاج إضافة قواعد مالية، ACL على مستوى الجهات والمحافظات، رقابة تغيير وصلاحيات تفويض وتوقيعات وبيئة اختبار مستقلة.

## خطة الإكمال قبل الاستخدام الرسمي

مرحلة 1: ورش اعتماد دقيقة مع المديرية الهندسية والعقود والقانونية والمالية والرقابة، ومصفوفة RACI والتفويض والسقوف المالية، وإجراءات 2025 الخاصة بكل نوع عقد. مرحلة 2: نموذج بيانات جداول كميات بنودياً، تقديرات كلفة ومرجع موازنة، نماذج محاضر وكتب رسمية، جداول وآجال اعتراضات وعضويات وتضارب مصالح. مرحلة 3: محرك مالي للمستخلصات والاستقطاعات والتأمينات وخطابات الضمان والسلف المقدمة والضرائب وتدقيق الحسابات والقيود البنكية. مرحلة 4: تكامل IDMS والمنصة الموحدة والتوقيع الإلكتروني والإشعارات والأرشفة، اختبار أمني واختبارات القبول ونشر حكومي مقيّد.

**تحذير**: الكود هنا Proof of Concept تنفيذي؛ قد تكون فيه نواقص أو أخطاء غير مكتشفة. لا تستخدمه وحده في قرارات إحالة أو دفع من المال العام.

## إصلاح مشاكل التشغيل على Windows / PowerShell

إذا عمل Vite على `http://localhost:5173` لكن ظهرت رسالة `ECONNREFUSED` عند تسجيل الدخول، فهذا يعني عادةً أن خادم API على المنفذ 4000 لم يبدأ.

من مجلد المشروع، بعد استلام التحديث (`git pull origin main`) تأكد من وجود ملف `.env` يحتوي:

```env
PORT=4000
JWT_SECRET=ضع-هنا-سلسلة-عشوائية-طويلة-لا-تقل-عن-32-رمزاً
BOOTSTRAP_ADMIN_USERNAME=admin
BOOTSTRAP_ADMIN_PASSWORD=اختر-كلمة-مرور-قوية-من-12-رمزاً-على-الأقل
DATABASE_PATH=./data/projects.sqlite
UPLOAD_DIR=./data/uploads
```

لإنشاء قيمة آمنة وفريدة لـ `JWT_SECRET` باستخدام PowerShell (لا تستخدم القيمة المثال):

```powershell
[Convert]::ToHexString([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

انسخ الناتج إلى `.env`. تستدعي `npm run dev` الآن `node --env-file=.env --watch server/index.mjs` لقراءة الإعدادات دون حزمة إضافية (Node.js 22+).

**ملحوظة:** لا يُعاد إنشاء المدير إذا كان موجوداً مسبقاً في قاعدة البيانات؛ تغيير `BOOTSTRAP_ADMIN_PASSWORD` لاحقاً لا يعيد تعيين كلمة المرور تلقائياً. لا تحذف قاعدة البيانات لتغيير كلمة المرور إن كانت تحتوي على بيانات.

بعد الإصلاح، يفترض ظهور `Projects Workflow API listening on 4000`، ويمكن اختبار `http://localhost:4000/api/health`.

## استعادة حساب المدير دون حذف البيانات

إذا ظهرت رسالة «اسم المستخدم أو كلمة المرور غير صحيحة»، راجع `.env`. **كلمة المرور الأقل من 12 رمزاً تُرفض في تهيئة المدير الأول**. تغيير `BOOTSTRAP_ADMIN_PASSWORD` وحده لا يغير حساباً سبق إنشاؤه.

1. أوقف التطبيق الجاري بـ `Ctrl+C`.
2. ضع كلمة مرور **جديدة وخاصة** لا تقل عن 12 رمزاً في `BOOTSTRAP_ADMIN_PASSWORD` داخل `.env`، واحتفظ باسم المستخدم `admin`. لا تنشر القيم السرية.
3. شغّل محلياً من جذر المشروع:

```powershell
git pull origin main
npm run admin:reset
npm run dev
```

الأداة `scripts/reset-admin-password.mjs` تفحص ملف SQLite المحدد في `DATABASE_PATH`: إذا لم يكن هناك مدير تنشئه، وإذا كان حساب المدير المقصود موجوداً تُحدّث **كلمة المرور فقط وتفعّل الحساب**، دون حذف المشاريع والمستندات والمستخدمين. إذا لم توجد قاعدة البيانات أو كان الاسم مستخدماً لدور غير إداري أو وجد مدير آخر باسم مختلف، تتوقف دون إنشاء قاعدة جديدة أو تغيير ذلك المستخدم.

ستظهر رسالة `SUCCESS` عند إتمام الاستعادة. إن ظهر خطأ آخر، شارك رسالة الخطأ من دون نشر كلمات المرور أو `JWT_SECRET`.


## تعبئة بيانات عراقية تجريبية كاملة — Windows

هذا خيار **محلي وتجريبي فقط**، ولا يعمل تلقائياً عند تشغيل النظام. يضيف 69 مشروعاً افتراضياً لعام 2026 موزعة على مراحل الإدراج والتدقيق واللجان والمناقصات والإحالات والعقود والمباشرة والسلف، مع مستخدمين تجريبيين، وأربع لجان، ووثائق PDF تجريبية قابلة للفتح، وعطاءات وموافقات وسجل أحداث. تستخدم البيانات أسماء محافظات وأقضية حقيقية وتقديرات مالية معقولة **لكن جميع الأرقام والجهات والمقاولين والقرارات والملفات مختلقة**. تبدأ رموز المشاريع بـ `DEMO-2026-` وعناوينها بـ `[DEMO]`.

أوقف `npm run dev` السابق باستخدام `Ctrl+C`، ثم نفذ في PowerShell:

```powershell
& {
  Set-Location 'C:\Users\GaithAhmed\Documents\ZN\projects-workflow'
  git pull origin main
  if ($LASTEXITCODE -ne 0) { throw 'فشل تحديث GitHub' }
  npm run demo:seed
  if ($LASTEXITCODE -ne 0) { throw 'فشل إدخال DEMO' }
  npm run dev
}
```

البيانات لا تحذف أو تغيّر المشاريع الحالية ولا تعيد تعيين كلمة مرور المدير. تشغيل `npm run demo:seed` مرة ثانية **لا يكرر** المشاريع التي تحمل رموز DEMO المحددة. تتم كتابة السجلات داخل معاملة SQLite واحدة، وتزال ملفات المستندات التي كُتبت في المحاولة إذا فشلت المعاملة. لا تنشئ الأداة نسخة احتياطية تلقائياً.

يُنشئ النظام كلمات مرور عشوائية مستقلة لمجموعة الحسابات التجريبية (مشتركة بين تلك المجموعة فقط)، ويحفظ أسماء المستخدمين وكلمة المرور في:

```text
data\DEMO_USERS_CREDENTIALS.txt
```

افتح هذا الملف على جهازك باستخدام `notepad .\data\DEMO_USERS_CREDENTIALS.txt`. الملف المحلي محفوظ تحت `data/` المستثنى من Git، ولا تُطبع كلمات المرور في سجل الأوامر. حساب `admin` يبقى كما هو. لا تنشر الملف أو تستخدم كلمات مرور DEMO في عمل حكومي فعلي.

إذا بقي التطبيق يعمل أثناء التعبئة، حدّث المتصفح بـ `Ctrl+F5` بعد نجاح الأمر.
